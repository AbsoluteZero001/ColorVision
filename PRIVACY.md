# ColorVision Privacy Policy

Effective date: 2026-09-15

ColorVision is a Windows application for local camera capture and color
recognition. This Privacy Policy explains how ColorVision processes camera images,
color measurements, configuration data, and logs, and when data may be sent to a 
server selected by the user.

## Scope

This policy applies to the ColorVision Windows application, its local backend,
and its local browser-based user interface.

ColorVision does not provide user accounts. It does not include advertising,
telemetry, third-party analytics, or crash reporting.

This policy does not govern a server that a user configures as an upload
target. That server is controlled by the user or another organization, and its
own privacy and security practices apply.

## Data Processed

ColorVision processes the following data when the corresponding feature is
used:

- Camera frames read from a physical camera or generated by the Mock Camera.
- Captured images and the image region selected for color analysis.
- Color results, including RGB, CIELAB, HEX, and ROI coordinates.
- A user-configured camera identifier and capture/upload timestamps.
- Configuration values used for the local service, uploads, logs, and
  retention.
- Local operational logs and local upload-history records.

The application does not ask for an account, password, payment information, or
contact details.

## Camera and Image Data

ColorVision accesses a camera through OpenCV on the local Windows computer. It
reads video frames for preview, capture, and color analysis. The application
does not capture audio.

When the workbench starts, the local browser interface asks the local backend
to detect and open an available camera. The user can instead use the Mock
Camera, which generates a synthetic image and does not use camera hardware.
Windows controls camera access through device and privacy settings.

Live frames are sent from the local backend to the local browser through the
computer's loopback interface for display. This is local communication, not an
Internet upload.

When the user selects "Capture", the current frame is saved as a JPEG file in
`data/captures/`. Color analysis is then performed locally. A captured image
may contain people, objects, documents, or other sensitive visual information.
Users should choose where they point the camera and should review images before
uploading them to any server.

## Local Processing and Storage

Color recognition is performed on the local computer. The browser sends the
captured image and selected ROI coordinates to the locally running ColorVision
API. The backend calculates RGB, CIELAB, HEX, and ROI values without sending
the image to ColorVision developer-operated servers.

ColorVision stores data locally in the application directory:

- `config/config.json` stores application settings, including the optional
  upload token.
- `data/captures/` stores JPEG images created by the Capture action.
- `data/logs/colorvision.db` stores upload-history records in SQLite.
- `data/logs/images/` stores the original image and ROI image associated with
  an upload when upload-log image storage is enabled.
- `data/logs/colorvision.log` stores operational logs.

The `data/results/` directory is created by the application, but the current
version does not write separate color-analysis result files there.

When local upload logging is enabled, a successful upload creates a record in
`upload_logs`. The record can contain:

- Upload time and capture time.
- Camera ID.
- RGB, CIELAB, HEX, and ROI values.
- Upload mode (`mock` or `api`).
- Server request ID and result message.
- Relative paths to locally saved upload images, when image storage is enabled.

The SQLite database stores the structured record and image paths. The image
files themselves are stored in `data/logs/images/`.

The application's local API and media routes are intended for the local
computer. In the managed Windows application, the backend binds to the
loopback interface.

## Remote Upload and Network Communication

By default, ColorVision does not upload data to an external server. The default
configuration uses Mock Upload mode (`mock_mode=true`), which simulates a
successful upload response and does not contact the configured API.

A real upload can occur only when the user configures the application for real
API mode by setting `mock_mode=false`. The target server is selected by the
user through `api_url`. If `api_url` points to another computer or an Internet
service, the uploaded data leaves the local computer.

There are two ways to trigger a real upload:

- The user selects "Upload Server" after completing a color analysis.
- The user enables and saves `auto_upload=true`. After that, a successful color
  analysis initiated by the user automatically starts the same upload process.

`auto_upload` is disabled by default. It is not a startup upload or a hidden
background process. It runs only after a user-initiated color analysis
completes.

A real upload sends a `multipart/form-data` request containing:

- The original captured image.
- The cropped ROI image.
- RGB, CIELAB, HEX, and ROI values.
- Camera ID and timestamp.

If the user has configured a token, ColorVision sends it to the configured
server as an `Authorization: Bearer` header. No token is sent when Mock Upload
mode is active. The configured server receives the images and metadata and may
store or process them according to its own policies.

ColorVision also makes local loopback requests for normal operation. These
include the health check, configuration requests, camera status requests,
image previews, and periodic camera-status checks while a camera is active.
These requests are directed to the ColorVision backend running on the same
computer. They are not requests to an external website.

At startup, the packaged application checks the local loopback service to
determine whether ColorVision is already running and opens the local page in
the default browser. It does not contact an external update or version-check
service.

Outside the upload paths described above, the application does not perform
automatic background Internet communication.

## Third-Party Services

The ColorVision codebase does not include advertising, telemetry,
third-party analytics, or crash-reporting services. It does not send usage
statistics to the project maintainers.

A server configured through `api_url` may be operated by the user or by a
third party. ColorVision does not control that server. Users should review the
privacy and security terms of any server they configure.

## Data Retention and Deletion

Captured images in `data/captures/` remain on the local computer until they are
removed by the application's retention settings or deleted manually.
`image_retention_days` and `max_image_count` control automatic cleanup. Both
default to `0`, which disables automatic cleanup by age or count.

When a new image is captured, ColorVision applies the current capture-retention
settings. The current version does not provide a separate UI button to clear
all original captured images. Users can remove those files directly from the
application directory after closing ColorVision.

Upload logs can be deleted individually or cleared entirely from the Logs
page. Deleting a log also removes the local upload images associated with that
record when managed by ColorVision. The application also applies
`log_retention_days` and `max_log_count` at startup and after recording a new
upload. Both settings default to `0`, which disables automatic cleanup by age
or count.

Disabling future upload logging does not automatically delete logs that were
already created. Existing logs remain until deleted through the Logs page, by a
retention rule, or manually.

The operational file `data/logs/colorvision.log` uses size-based rotation and
retains up to three backup files. It is not controlled by the upload-log
retention settings.

ColorVision cannot delete copies of uploaded data that a user-configured
server has already received or retained. Deletion requests concerning that
server must be directed to its operator.

For a standard installation, local application data can be removed by deleting
the ColorVision application directory, including its `config/` and `data/`
directories. If a custom configuration path was explicitly configured, that
file must be removed separately.

## Credentials and Configuration

ColorVision does not require an account password. The optional upload token is
stored as plain text in the local `config/config.json` file. The Settings page
masks the token while it is displayed, but the application does not encrypt
the stored value.

The token is used only for real upload requests and is sent to the server
specified by the user's `api_url`. It is not sent during Mock Upload. The
application code does not intentionally write the token value to
`colorvision.log`.

Users should protect the local Windows account and the ColorVision
configuration file. Anyone who can read or copy `config/config.json` may be
able to obtain the stored token.

## Security

ColorVision is designed primarily as a local Windows application, but no
software or network transmission can be guaranteed to be free of risk. Users
are responsible for securing their computer, files, camera, network, and
selected upload server.

Local images, SQLite records, operational logs, and configuration data are not
encrypted by the application. The token in `config/config.json` is also stored
without encryption. The local API does not provide an account-based
authentication layer.

The upload URL may use either HTTP or HTTPS. ColorVision does not force HTTPS.
For any server reached over an untrusted network, users should use an HTTPS
endpoint and protect the configured token. The security of data after it
reaches the selected server depends on that server and its operator.

ColorVision may include the configured API URL in a local operational log when
an upload request fails.

## Children's Privacy

ColorVision is a general-purpose color capture and recognition tool. It does
not provide accounts, profiles, advertising, or features directed specifically
at children, and it does not request age information.

Camera images may contain children or other sensitive subjects. Users should
only capture and upload such images when they have the necessary permission
and should supervise use by children.
